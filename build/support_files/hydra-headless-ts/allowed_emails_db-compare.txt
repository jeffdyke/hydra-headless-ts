# DEV SAMPLE -> copy to /etc/hydra-headless-ts/allowed_emails_db-compare.txt
#
# Per-resource allowlist for `db-compare` (the DBHub MCP endpoint). Checked *in
# addition to* allowed_emails.txt, never instead of it -- an address must pass
# both, so removing someone from the global list revokes every resource.
#
# If this file is missing or unreadable the app denies EVERYONE rather than
# falling back to the global list (isEmailAllowedForResource in
# src/fp/services/emailAllowlist.ts returns false on a null list). That is the
# safe default, but it presents as a bare 403 from /authz with
# "authz denied: not on the resource allowlist" in the headless-ts log -- easy to
# mistake for a bad token, since the token itself verified fine to get that far.
#
# Format: bare lines are domains, lines containing @ are individual addresses,
# # comments and blank lines ignored.
#
# ADD YOUR OWN ADDRESS -- the one in your Google ID token's `email` claim, which
# is not necessarily the account you think: check with
#   node scripts/dev-google-token.mjs   (it prints the email)
# or `npm run validate-token -- $TOK`.
#
# Deliberately individual addresses rather than a bare `bondlink.com` domain, so
# this stays structurally the same as the deployed list. There, db-compare
# exposes several production hosts including the primary, so it is restricted to
# named people; adding the domain would silently undo that. Locally DBHub points
# at whatever dbhub.toml names, but keeping the same shape avoids a habit that
# would be wrong in staging.

# your.name@bondlink.com
